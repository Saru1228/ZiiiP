# 009 - 最终 Kill Test 结论：可以继续，但方向要变

## 一句话结论

这条路 **没有死**，而且值得继续。

但它现在还不是一个能直接拿去比赛的压缩方案。最新实验说明：真正有价值的东西藏在“低维修正方向”里；下一步要解决的是，怎样在不偷看答案的情况下，提前猜出这些修正。

## 这次做了什么

我们按照 `007.md` 做了三关验证：

1. 换几段不同的文本，看效果是不是稳定。
2. 只在第一段文本上学一个“方向”，再拿去别的文本段上用，看它是不是泛化。
3. 做一个很强的“上限实验”：假设我们能知道正确答案，然后看低维空间里到底有没有足够的压缩价值。

前两关已经通过。

这次继续完成了第三关。

## 第一关结果：稳定

我们测了 4 段互不重叠的 1MB 文本。

普通低秩方法在四段里都能追回大约 21% 到 24% 的差距。

平均值是 **22.64%**。

这说明它不是只在第一段文本上偶然有效。

## 第二关结果：能迁移

我们只用第一段文本学方向，然后拿去另外三段文本上用。

结果不但没有崩，反而每段都有 22% 以上的追回效果。

平均是 **23.61%**。

这说明“方向”本身比较稳定，不是完全贴着某一段文本过拟合。

## 第三关结果：上限很高

第三关是最关键的。

它问的是：

如果给这个低维空间一个非常有利的条件，它到底有没有潜力？

结果非常强：

| rank | 压缩后大小 | 相比 PPMD 少多少 |
|---:|---:|---:|
| 8 | 158,356 bytes | 少 17,982 bytes |
| 16 | 118,852 bytes | 少 57,486 bytes |
| 32 | 51,214 bytes | 少 125,124 bytes |
| 64 | 6,103 bytes | 少 170,235 bytes |

这里的数字非常大，是因为第三关用了 oracle，也就是“偷看了正确答案”的上限实验。

所以它不能直接当成真实压缩器。

但它说明了一件很重要的事：

**低维空间里确实有很强的压缩价值。**

之前普通 PCA 只能追回 22% 左右，不是因为这个方向没价值，而是因为我们还不会正确选择每个位置该怎么修正。

## 这意味着什么

可以把当前结果理解成：

以前我们知道地下可能有矿。

第一关、第二关说明：矿不是只在一个小地方，它比较稳定。

第三关说明：矿的含量其实很高。

但现在的问题是：我们还没有一台真正能用的采矿机器。

也就是说，接下来不应该主要去做 10MB、100MB 的扩大测试。

现在最该做的是：

**训练一个不偷看答案的预测器，让它提前猜出低维修正系数。**

## 最终判断

按照 `007.md` 的规则，这次是：

**STRONG GO**

也就是：继续研究，而且优先级提高。

但要特别注意：

这不是“已经成功压缩 enwik9”的结论。

更准确的说法是：

**这条技术路线有足够强的上限，值得进入下一阶段。下一阶段的核心任务，是把 oracle 变成合法预测。**

## 下一步建议

下一步不要先扩大到 10MB/100MB。

建议先做一个小而清楚的新实验：

用合法信息预测 oracle 的低维系数。

合法信息可以包括：

- PPMD 给出的概率形状
- Transformer 给出的概率形状
- 熵、置信度、top-k 概率
- 当前上下文特征
- 前面位置的修正状态

第一目标不用太高。

如果不偷看答案的预测器能稳定追回原始差距的 10% 到 20%，这条路就真的进入了可工程化阶段。
