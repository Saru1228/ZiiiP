# Local Agent Experiment Plan
## Transformer × PPMD 残差低维结构实验说明书

日期：2026-10-08

---

# 0. Agent 角色

你是一个本地实验型 Coding Agent。

你的任务不是大规模训练，不是重构整个压缩器，也不是尝试大量无关模型。

你的核心任务是：

> 在现有 1MB 小样本实验框架上，系统判断 Transformer 相对于 PPMD 提供的概率修正，是否具有可压缩的低维、稀疏、局部或非线性结构。

实验应以：

- 最小改动
- 可重复
- 可比较
- 可回滚
- byte-level 最终结果优先

为原则。

不要为了“模型看起来更先进”而引入复杂方法。

最终评价标准始终是：

```text
最终压缩文件大小（bytes）
```

辅助指标可以使用：

```text
NLL
cross entropy
KL divergence
概率重构误差
explained variance
```

但辅助指标不能替代最终压缩结果。

# 1. 当前已知事实

当前实验规模：

```text
1MB
```

当前基线：

```text
完整 Transformer：175,130 bytes
保存概率再回灌 Transformer：175,130 bytes
直接 PPMD 概率：176,338 bytes
rank 1 PCA：176,460 bytes
rank 16 PCA：176,361 bytes
rank 64 PCA：176,294 bytes
```

因此：

```text
PPMD → Transformer 可争取空间：

176338 - 175130
= 1208 bytes
```

当前 rank64 相对 PPMD 改善：

```text
176338 - 176294
= 44 bytes
```

追回比例约：

```text
44 / 1208
≈ 3.64%
```

所以目前结论是：

```text
raw probability + global PCA
存在极弱正向信号，
但不足以支持直接扩大数据规模。
```

当前不要直接运行：

```text
10MB
100MB
更大的 Transformer
长时间训练
大规模 hyperparameter search
```

必须首先确认：

```text
低维结构是否真的存在
```

以及：

```text
当前 PCA 是否只是用了错误的坐标系或错误的目标函数
```

---

# 2. 总研究问题

整个下一阶段只回答三个核心问题。

## Q1. 坐标系是不是错了？

当前 PCA 直接作用于 probability space。

需要比较：

```text
raw probability residual
```

与：

```text
log-ratio residual
```

判断概率单纯形上的结构是否比普通欧氏空间更适合低秩表示。

---

## Q2. 优化目标是不是错了？

普通 PCA 优化：

```text
L2 reconstruction error
```

但压缩真正关心：

```text
真实符号的 -log probability
```

因此需要判断：

```text
最大方差方向
```

是否等价于：

```text
最有压缩价值的方向
```

预计二者未必一致。

---

## Q3. 全局线性假设是不是错了？

当前方法假定：

```text
所有 context 的 Transformer residual
共享一个全局低维线性子空间
```

需要验证：

```text
不同 context 状态
是否对应不同局部低维结构
```

如果局部低秩显著好于全局低秩，则说明 residual 更接近：

```text
piecewise low-dimensional manifold
```

而不是单一 linear subspace。

---

# 3. 总实验原则

所有实验首先继续使用：

```text
1MB
```

除非满足后面的“扩大规模条件”。

所有实验必须保持：

```text
相同输入文件
相同 tokenizer / alphabet
相同 arithmetic coder
相同概率量化方式
相同编译版本
相同 roundtrip 流程
```

不要同时修改：

```text
概率模型
算术编码器
量化规则
文件格式
测试数据
```

每次实验尽量只改变一个因素。

---

# 4. 基础 sanity check

开始任何新实验前，必须再次确认：

```text
完整 Transformer 路径
=
保存概率再重新回灌路径
```

预期：

```text
175130 bytes
=
175130 bytes
```

如果不一致：

```text
立即停止后续实验。
```

先修复概率保存、加载、量化或 roundtrip 差异。

---

# 5. 统一符号

定义：

```text
pP[t]
```

表示位置 `t` 上 PPMD 给出的完整概率分布。

定义：

```text
pT[t]
```

表示位置 `t` 上 Transformer 给出的完整概率分布。

假定 alphabet 大小约：

```text
D = 205
```

所有概率必须：

```text
p[i] > 0
sum(p) = 1
```

如果存在 0 probability，使用统一 epsilon：

```text
eps = 1e-9
```

或使用当前工程已有的最小概率规则。

不得为不同实验偷偷修改 epsilon。



# 7. Experiment B：Log-ratio residual PCA

这是下一阶段最高优先级实验。

---

# 7.1 动机

概率向量不属于普通无约束欧氏空间。

它们满足：

```text
p_i > 0
sum p_i = 1
```

所以不要直接建模：

```text
pT - pP
```

而是建模：

```text
log pT - log pP
```

这可以理解为：

```text
Transformer
相对于
PPMD
对每个 symbol 做多少 multiplicative correction
```

---

# 7.2 构造 residual

对于每个位置 `t`：

```text
r[t, i]
=
log(pT[t, i] + eps)
-
log(pP[t, i] + eps)
```

随后去掉整体平移：

```text
r_centered[t]
=
r[t] - mean(r[t])
```

这样得到：

```text
shape = [N, D]
```

---

# 7.3 PCA

分别测试：

```text
rank =
1
2
4
8
16
32
64
```

保存：

```text
basis
latent
explained_variance
reconstructed_residual
```

---

# 7.4 概率重构

不要直接：

```text
pP + residual
```

而是：

```text
q_i
=
pP_i * exp(alpha * reconstructed_r_i)
```

然后：

```text
q = q / sum(q)
```

即：

```text
q_i ∝ pP_i exp(alpha * r_hat_i)
```

---

# 7.5 alpha

测试：

```text
alpha =
0.10
0.20
0.40
0.60
0.80
1.00
```

如果最佳点明显落在 0.1 以下，再追加：

```text
0.02
0.05
```

如果最佳点接近 1.0，不需要测试大于 1，除非结果明确提示 overshoot 有益。

---

# 7.6 输出

生成：

```text
output/logratio_pca_results.csv
```

字段：

```text
rank
alpha
compressed_bytes
delta_vs_ppmd
delta_vs_transformer
gap_recovered_percent
explained_variance
nll
```

---

# 7.7 成功判据

若：

```text
gap_recovered_percent >= 10%
```

视为：

```text
存在值得继续研究的信号
```

若：

```text
>= 20%
```

视为：

```text
明显正向
```

若：

```text
>= 40%
```

视为：

```text
强信号
```

若所有 rank / alpha：

```text
<= 5%
```

则暂时认为：

```text
单纯改变概率几何坐标不足以解决问题
```

# 8. Experiment C：Loss-aware low-rank

仅在 Experiment B 完成后进行。

不要一开始就做复杂优化。

---

# 8.1 研究问题

普通 PCA 最小化：

```text
||r - r_hat||²
```

但 codec 关心：

```text
-log q[y]
```

因此需要判断：

```text
低 L2 error
```

是否等价于：

```text
低 coding loss
```

---

# 8.2 第一版实现

不要直接设计复杂新网络。

优先实现一个简单可优化模型：

```text
r_hat_t = U z_t
```

其中：

```text
U: D × K
z_t: K
```

然后：

```text
q_t
=
normalize(
pP_t * exp(U z_t)
)
```

损失：

```text
loss
=
mean(
-log q_t[y_t]
)
```

可附加：

```text
L2 regularization
```

避免 residual 无限制放大。

---

# 8.3 rank

只测试：

```text
K =
4
8
16
32
```

不要做大规模 grid search。

---

# 8.4 Oracle 与实际模型要分开

如果每个位置的：

```text
z_t
```

是直接通过目标文件优化出来的，那么该实验属于：

```text
oracle experiment
```

必须在日志和结果中明确标记：

```text
ORACLE
```

不能将其解释为可直接部署 codec。

Oracle 实验只回答：

```text
这种低维表示理论上有没有容量
```

# 9. Experiment D：局部低秩 / Piecewise Manifold

这是验证“流形假说”的关键实验。

优先级高于普通 Autoencoder。

---

# 9.1 核心思想

如果所有 context 混在一起时 residual 是弯曲的：

```text
global PCA
```

可能需要很高 rank。

但若按 context 状态切开：

```text
local PCA
```

可能每一区域都只需要很小 rank。

---

# 9.2 不允许使用的信息

分桶只能使用 decoder 端天然可获得的信息。

不要根据：

```text
真实 next symbol
Transformer hidden state
未来 token
完整 Transformer probability
```

进行分桶。

---

# 9.3 第一组分桶特征

优先使用 PPMD entropy：

```text
H(pP)
=
-sum(pP * log(pP))
```

按样本分位数划：

```text
4 buckets
```

例如：

```text
Q1
Q2
Q3
Q4
```

使各 bucket 样本量基本接近。

---

# 9.4 每个 bucket 单独 PCA

在每个 bucket 内对：

```text
log-ratio residual
```

单独做 PCA。

测试：

```text
local rank =
4
8
16
```

因此模型结构类似：

```text
4 buckets × rank8
```

---

# 9.5 必须比较参数预算

至少比较：

```text
global rank32
```

vs：

```text
4 × local rank8
```

因为它们的 basis 参数规模大致处于同一量级。

不要只比较：

```text
global rank8
vs
4 × rank16
```

然后声称 local 更好。

---

# 9.6 第二组可选 context 特征

若 entropy 分桶出现正向信号，再测试：

```text
PPMD top1 probability
top1 - top2 margin
PPMD effective context/order
entropy + context order
```

不要一次性全部组合。

---

# 9.7 成功判据

如果：

```text
local low-rank
```

在类似参数预算下明显超过：

```text
global low-rank
```

例如：

```text
global rank32:
recover 8%

4 × local rank8:
recover 20%
```

则记录结论：

```text
Evidence for context-conditioned
piecewise low-dimensional structure.
```

这时才值得进一步称其为：

```text
manifold-like residual structure
```

# 10. Experiment E：Sparse / Top-k correction

---

# 10.1 动机

Transformer 的收益可能不是来自：

```text
重新调整全部 205 个 symbol
```

而主要来自：

```text
重新调整概率最高的一小部分 symbol
```

---

# 10.2 测试

根据 PPMD probability 排序。

测试：

```text
top-k =
4
8
16
32
64
```

只允许低秩 residual 修改：

```text
PPMD top-k symbols
```

其余 tail 保留相对比例或整体 tail mass。

---

# 10.3 第一版建议

简单实现：

对于 top-k：

```text
q_i
=
pP_i * exp(r_hat_i)
```

对于其他：

```text
q_i = pP_i
```

最后统一：

```text
renormalize
```

---

# 10.4 重点观察

如果：

```text
top16
```

已经能恢复完整 205 维 correction 的大部分收益，则意味着：

```text
signal is sparse
```

这会明显降低后续模型复杂度。

# 13. 额外诊断：Transformer 到底在哪些位置赢？

这个分析优先级很高，计算成本很低。

对于每个位置计算：

```text
gain_t
=
-log2(pP_t[y_t])
+
log2(pT_t[y_t])
```

等价于：

```text
gain_t
=
log2(
pT_t[y_t] / pP_t[y_t]
)
```

解释：

```text
gain_t > 0
Transformer 更好

gain_t < 0
PPMD 更好
```

输出：

```text
gain distribution
gain vs PPMD entropy
gain vs top1 probability
gain vs context order
```

重点判断：

```text
Transformer 的优势是广泛分布，
还是集中在少数困难 context。
```

如果收益高度集中，则应该优先研究：

```text
gating
conditional correction
sparse correction
```

而不是全局修正。

# 20. 扩大到 10MB 的条件

不要因为某个实验比 PPMD 好几个 byte 就扩大。


## 条件 B

出现明确机制：

例如：

```text

```

或：

```text

```

如果条件允许，后期应测试：

```text

```
