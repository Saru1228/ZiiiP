# 006_FINAL_NON_ORACLE_KILL_TEST.md

你是本项目的最后一轮验证 Agent。

你的任务不是继续寻找“还有什么模型可以试”，而是回答一个二元问题：

> 在不知道下一个 byte、也不运行完整 Transformer 的情况下，能否仅利用 decoder 合法可得的 context，预测出足够有用的低秩 correction，使最终 cmix 压缩结果稳定改善？

# 2. Gate 3 Oracle 不作为可部署证据

已有 oracle 实验允许：

```text
true next byte y_t
```

参与选择：

```text
z_t
```

因此类似：

```text

rank64 -> 14092% recovery
```

不能解释成：

```text

```

它只能说明：

```text

```

本轮严禁再次使用这种 oracle 结果作为 GO 理由。

# 16. Non-oracle probability reconstruction

预测：

```text
z_hat_t
```

后：

```text
r_hat_t =
B_K z_hat_t
```

然后：

```text
q_t,i
∝
pPPMD_t,i
*
exp(r_hat_t,i)
```

归一化：

```text
q =
q / sum(q)
```

如果已有稳定 alpha 机制，可以测试：

```text
alpha = 0.8
```

作为固定值。

不要重新进行 alpha sweep。

# 23. FINAL DECISION RULES

以下阈值在看到结果以后不得修改。

---

# STOP

满足任何一条：

```text
mean test recovery < 10%
```

或：

```text
任何 2 个 final test slices <= 0%
```

或：

```text
只有 validation 正向，
final test 不稳定
```

或：

```text
成功依赖 Transformer inference feature
```

或：

```text
成功依赖 true next byte
```

或：

```text
需要 >250k 参数才勉强达到 10%
```

则：

# STOP PROJECT

不要再试：

```text
Autoencoder
VAE
LSTM
Transformer predictor
更多 manifold
更多 ranks
更多 alpha
更多 buckets
10MB / 100MB
```

归档项目。

---

# GO

必须同时：

```text
mean final-test recovery >= 10%
```

并且：

```text
所有 final test slices > 0%
```

并且：

```text
minimum test recovery >= 5%
```

并且：

```text
no Transformer at inference
no target leakage
```

并且模型保持：

```text
small / cheap
```

则：

```text
GO
```

允许进入下一阶段。

---

# STRONG GO

必须满足：

```text
mean final-test recovery >= 20%
```

并且：

```text
minimum recovery >= 10%
```

并且：

```text
所有 held-out slices 正向
```

并且：

```text
predictor <= 250k parameters
```

并且：

```text
不运行 Transformer
不使用 future information
```

则：

# STRONG GO

此时才允许：

```text
10MB validation
runtime optimization
model quantization
real codec integration
competition-oriented evaluation
```

# 24. 为什么 5%-10% 也停止

不要因为：

```text
比 PPMD 好几十 bytes
```

就自动继续。

当前目标不是证明：

```text
存在一点 signal
```

这个事实已经证明过。

现在要证明：

```text
signal 强到足以值得工程投入。
```

如果最终 cheap non-oracle predictor 只能恢复：

```text
5%-10%
```

意味着部署、模型成本、运行时间和泛化损失之后，

现实收益很可能更低。

因此：

```text
<10% = STOP
```

不要修改该规则。
