# 6. Gate 3 — Mixer-Aware Low-Rank ORACLE

只有 Gate 1 和 Gate 2 都 PASS 后执行。

这是最终 Gate。

---

# 6.1 核心问题

目前 PCA 优化：

```text
residual reconstruction L2
```

但实验已经发现：

```text
downstream probability NLL
```

并不可靠对应：

```text
最终 cmix compressed bytes
```

说明 Transformer downstream probability 更可能是：

```text
mixer feature / expert signal
```

而不是最终概率预测器。

因此最终问题不是：

> 能否逼近 Transformer probability？

而是：

> 一个低维 correction 能否保留 Transformer 对最终 mixer 的大部分价值？

---

# 6.2 禁止错误目标

不要只优化：

```text
MSE(residual)
```

不要只优化：

```text
NLL of downstream q
```

如果最终 cmix mixer 的 differentiable objective 难以获得，可以使用尽可能接近：

```text
final mixer log-loss
```

的代理。

最终仍必须通过：

```text
actual compressed bytes
```

验证。

---

# 6.3 实验允许 ORACLE

本阶段允许：

```text
使用完整 Transformer data
```

允许：

```text
每个位置存在 oracle latent z_t
```

允许：

```text
离线优化 latent
```

因为目的不是部署。

目的只有：

> 判断低维表示本身是否有足够容量。

必须在所有输出标记：

```text
ORACLE
```

---

# 6.4 Rank

只测试：

```text
rank =
8
16
32
64
```

不要测试更多。

---

# 6.5 模型形式

推荐：

```text
r_hat_t = U z_t
```

然后：

```text
q_t
∝
pPPMD_t * exp(r_hat_t)
```

或等价的当前 log-ratio correction 形式。

重点变化：

```text
U / z
```

的优化目标必须与：

```text
最终 mixer / coder performance
```

尽可能一致。

---

# 6.6 alpha

为了避免重新进行巨大 grid search：

第一轮固定：

```text

```

如果优化参数本身已经吸收 scale，则不再单独使用 alpha。

如实现必须保留 alpha，则最多测试：

```text
0.5
0.8
1.0
```

不得扩大。
